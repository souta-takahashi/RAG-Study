2. 実装した手順
1. Pythonの開発環境構築
   - RAG専用フォルダを作成
   - 仮想環境 .venv を作成
   - Ollama・ChromaDBをインストール
   重要コマンド：
   py -3.14 -m venv .venv
   .venv\Scripts\activate
   py -m pip install ollama chromadb
2. ローカルAIの動作確認
   
   test_ollama.py を作成。
   
   PythonからOllamaを経由してQwen2.5に質問し、回答を取得しました。
   
   学んだこと：ollama.chat() はAIに質問を送信する機能。
3. 文章のベクトル化
   
   test_embedding.py を作成。
   
   Nomic Embed Textを使用して文章を768次元のベクトルに変換しました。
   
   学んだこと：Embeddingは文章の意味を数値配列として表現する技術。
4. ChromaDBへの登録
   
   test_chroma.py を作成。
   
   文章とベクトルをデータベースに保存しました。
   
   学んだこと：
   - PersistentClient()：データベースをローカルに保存
   - get_or_create_collection()：保存先のコレクションを取得・作成
   - upsert()：新規登録または既存データの更新
5. ベクトル検索の実装
   
   test_search.py を作成。
   
   質問をベクトル化し、ChromaDBから意味的に近い文章を検索しました。
   
   実際に「修正プログラムが公開される前の脆弱性を悪用する攻撃は？」という質問から、ゼロデイ攻撃の説明文を検索できました。
   
   学んだこと：文字列が一致しなくても意味的な類似性で検索できる。
6. RAGの基本機能を完成
   
   rag_chat.py を作成。
   
   検索結果を context に格納し、質問と一緒にQwen2.5へ渡しました。
   
   これによって、検索した資料を根拠にAIが回答する仕組みが完成しました。
7. 外部ファイルの読み込み
   
   register_documents.py を作成。
   - TXTファイルの読み込み
   - PDFファイルの読み込み
   - チャンク分割
   - ベクトル化
   - ChromaDBへの登録
   PDFからの文章抽出と登録にも成功しました。
8. 検索元の情報を取得
   
   search_documents.py を作成。
   
   検索結果にファイル名・ページ番号・チャンク番号を表示できるようにしました。
9. AIの回答に出典情報を追加
   
   最後に rag_chat.py を改良。
   
   検索された文章だけでなく、その文章のファイル名やページ番号もAIに渡し、回答の根拠を表示する仕組みを追加しました。
3. RAGの全体像を理解する
今回実装したRAGは、次の流れで動いています。
RAGの処理フロー
① 資料の読み込み

PDF・TXT


② チャンク分割

長い文章を小さく分ける


③ Embedding

Nomicで文章を768次元に変換


④ ChromaDBに保存

文章・ベクトル・メタデータ


⑤ ユーザーが質問

質問もEmbeddingで数値化


⑥ 類似度検索

質問に近い文章を取得


⑦ contextを作成

検索結果を質問と一緒にまとめる


⑧ Qwen2.5が回答

資料を参考に回答を生成


この仕組みは、OllamaのEmbedding APIとChromaDBの検索・保存機能を組み合わせたものです。
GitHub+2

4. 今回、特に重要だった5つの用語
今後の学習でも何度も出てくるので、ここは覚えておきたいところです。
用語	簡単な説明
Embedding	文章を数値ベクトルに変換する
Vector Database	ベクトルを保存・検索するDB
Chunking	長い文章を小さく分割する
Retrieval	質問に関連する情報を検索する
Context	AIに渡す参考情報

そして、最も重要な理解はこれです。

RAGはAIに新しい知識を再学習させる技術ではありません。

質問のたびに必要な資料を検索し、その資料をAIに渡して回答を生成させる技術です。
5. 今回の実装で覚えておきたい注意点
今後の開発に向けて、3点補足します。

1. 登録件数について

ChromaDBの登録件数はファイル数ではなくチャンク数です。同じIDを upsert() すると新規追加ではなく更新になります。
GitHub+1


2. PDFの読み込みについて

   現在は文字を抽出できるPDFに対応しています。スキャン画像型PDFにはOCRが必要です。

3. 出典情報について

   AIに出典を文章で生成させるだけでは、誤ったページ番号を回答する可能性があります。今回のようにPython側でもメタデータから出典を表示する方法がより確実です。
